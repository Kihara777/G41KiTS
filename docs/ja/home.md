# home
[中文](../zh/home.md) | [English](../en/home.md) | 日本語

サイトコアデータ — キャラクターメッセージ、テーマカラー、ステータスコード、i18n。homete タイル（G41KiTS プロジェクト紹介）を直接提供します。

## 基本情報

| 項目 | 値 |
|------|-----|
| 種類 | data + tile |
| 依存 | core, nginx, redis |
| compose | none |

## 提供内容

- **タイル**：tile_homete（G41KiTS プロジェクト概要と技術スタック）
- **グローバル i18n**：キャラクター会話、挨拶 — JA / ZH / EN
- **データファイル**：chars.json、colors.json、langs.json、status.json
- **Web リソース**：ホームページ HTML、JS、CSS、画像
- **サイト設定**：SSL/TLS 基本設定、HSTS、エラーページ（prefix=0）

## インストール

```bash
./g41.sh kits add home
```

## 初回表示（起動リングと失敗状態）

初回表示は `G41.js` の 6 本のデータ要求（tiles / chars / status / 3 言語の i18n）が
すべて揃うまで `init()` を待ち、それまで `#g41-app` は `opacity:0` のままです。
その空白を埋めるのが `#g41-loading` の **WP8 起動リング**です。

**なぜスタイルを `G41.html` に内聯しているか**：三つの `.css`（約 15KB）は以前**描画をブロック**
していました —— HTML が届いても白画面のままで、最初の画素はスタイルシートを待っていました。
スタブで 3 秒遅延させた実測では、内聯後に First Contentful Paint が
**3024 / 6908ms → 36 / 928ms**、`performance` に `/css/` の要求は一切現れません。
**初回表示の要求は HTML 一つだけ**で、リングは最初のバイトで描けます。スタイルは `G41.html` の
`<style>` を編集してください —— 単独の `.css` ソースはもうありません（二つあれば必ずずれます）。

**幾何と色**：環と点の径は `vmin` でスケール（手機で約 99px / 9px）、五点は 72° 等間隔、
**点径は固定**、色は `--wp-amber`、背景は**不透明な黒**（WP8 の起動画面はもともと純色で、
立ち絵が視線を奪う問題も消えます）。環の下に**見える**「読み込み中 / Loading」があります
（i18n はまだ読めていないため、静的な二言語）。

**アニメーションは 3 段階の周期**（3.2 秒）：

| 段階 | 実装 | 判据（1 周期のサンプリング） |
|------|------|------------------------------|
| 進場 | 各点は透明度だけで現れ、五点が 0.12 秒ずつずれる | 可視点数 `0 → 1 → 2 → 3 → 4 → 5` |
| 回転 | 環全体が回転。`cubic-bezier(.55,.05,.45,.95)` が緩急を作る | 環の角度が単調に進む |
| 退場 | 同じずれで消えていく | 可視点数 `5 → 4 → … → 0`、その後約 0.36 秒の空白 |

点径と位置はアニメーション中に変わりません（変わるのは `opacity` だけ）ので、
「点の大きさが固定」は計測できます：五つの `::after` の計算幅はすべて等しい。
`prefers-reduced-motion` では両方のアニメーションを切り、五点が静止して全点灯します。

| 状態 | 切り替える側 | 表示 |
|------|-------------|------|
| 起動中 | なし（CSS のみ） | 琥珀色の 5 点リング（ビューポート中央） |
| 準備完了 | `applyStatus()` から呼ばれる `revealApp()` | **先**に環をしまい、**次に** `requestAnimationFrame` で入場クラスを付けてフェードイン |
| 起動失敗 | `bootFailed()` | リングを「読み込みに失敗しました / Failed to load」＋実際のエラー文に置換 |

**環をしまう順序も判据**：`main-entry` は以前 `init()` で付いていたため、入場アニメーションが
`opacity:0` の舞台裏で終わり、環が明けると「静止した完成品」が見えていました。現在の実測順序は
`ring 1 →（0.28 かつ entry:true・tiles:12）→ app 1 → 環が消える` —— 磁貼の準備と入場アニメーションが
同じフレームで、環も同時にフェードを始めます。

**リングを回しっぱなしにしてはいけません** —— 回り続けることは「まだ読んでいる」という主張です。
`bootFailed()` が存在する理由はそこにあります。

### スクリプトの順序は判据であって、趣味ではありません

```html
<script src="/js/tiles.js"></script>   <!-- 先に実行：closeDetail / buildTiles はここ -->
<script src="/js/G41.js"></script>     <!-- 実行と同時にデータ要求を始め、そのコールバックが上を使う -->
```

逆順だとコールドスタート（キャッシュなし）でデータが先に返ることがあり、`init()` が
`ReferenceError: closeDetail is not defined` を投げて頁全体が `opacity:0` のまま止まります。
**2026-10-12 の実測：修正前はコールドスタート 5/5 が白画面**。`tiles.js` を 3 秒遅らせれば
ローカルのスタブで確定的に再現できます。`tiles.js` のトップレベルは関数宣言だけで
`G41.js` に依存しないため、先に実行しても安全です。
